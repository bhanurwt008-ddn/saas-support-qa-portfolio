Professional Bug Reporting – SaaS Application

Project Overview

This project demonstrates how to identify, document, classify and report software defects in a SaaS application.

Bug Report Structure

A professional bug report should include:

- Bug ID
- Bug Title
- Environment
- Preconditions
- Steps to Reproduce
- Expected Result
- Actual Result
- Severity
- Priority
- Evidence
- Status

Sample Bug Report 01

Bug ID: BUG-001

Title: Login button does not respond after entering valid credentials.

Module: Login

Environment: Chrome / Windows

Precondition: User has a valid test account.

Steps to Reproduce:

1. Open the login page.
2. Enter valid email and password.
3. Click the Login button.

Expected Result: User should successfully log in.

Actual Result: Login button does not respond.

Severity: High (illustrative)

Priority: High (illustrative)

Status: Open (sample)

Sample Bug Report 02

Bug ID: BUG-002

Title: Error message is not displayed when the email field is empty.

Module: Login

Steps to Reproduce:

1. Open the login page.
2. Leave the email field empty.
3. Enter a password.
4. Click Login.

Expected Result: A required-field validation message should appear.

Actual Result: No validation message appears.

Severity: Medium (illustrative)

Priority: Medium (illustrative)

Status: Open (sample)

Sample Bug Report 03

Bug ID: BUG-003

Title: Password visibility icon does not work.

Module: Login

Steps to Reproduce:

1. Open the login page.
2. Enter a password.
3. Click the show-password icon.

Expected Result: Password should become visible.

Actual Result: Password remains hidden.

Severity: Low (illustrative)

Priority: Low (illustrative)

Status: Open (sample)

Severity vs Priority

Severity: Measures the impact of a defect on application functionality.

Priority: Indicates how urgently the defect should be fixed.

Severity| Meaning
Critical| Application or major functionality unavailable
High| Important functionality affected
Medium| Partial functionality affected
Low| Minor issue or cosmetic defect

Conclusion

Clear bug reporting improves communication between QA testers, support specialists and developers.

Note: All three defects are hypothetical examples, not verified defects in a live application.
